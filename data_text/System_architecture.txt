1. TỔNG QUAN KIẾN TRÚC HỆ THỐNG
--------------------------------------------------------------------------------
Hệ thống được thiết kế theo kiến trúc Modulith với AI-service là 1 service độc lập, với mô tả sau:
- Client (Frontend React / Vite App)
- Business & Storage Controller (Backend Spring Boot Server)
- Pure Vision AI Engine (AI Microservice Python)
- Streaming Gateway (MediaMTX RTSP/WebRTC Server)
- Infrastructure Layer (Database PostgreSQL + pgvector, MinIO Object Storage, Apache Kafka)


2. PHÂN CÔNG VAI TRÒ CHI TIẾT
--------------------------------------------------------------------------------

2.1. FRONTEND CLIENT (React + Vite)
- Giao diện quản trị tài khoản, xem luồng camera thời gian thực, quản lý các vụ việc an ninh.
- Kết nối trực tiếp với MediaMTX Gateway qua giao thức WebRTC (WHEP) / HLS để xem live stream video độ trễ cực thấp (< 0.5s) trên màn hình Guard Console.
- Gửi yêu cầu khởi tạo tài khoản qua REST API (`POST /api/users/staff-accounts`) đính kèm `faceImage`.
- Nhận thông báo cảnh báo vi phạm an ninh thời gian thực thông qua kết nối WebSocket (STOMP).

2.2. MEDIA STREAM GATEWAY (MediaMTX)
- Tiếp nhận trực tiếp các luồng video RTSP từ hệ thống IP Camera trên trường học.
- Phân phối luồng RTSP cho AI Service xử lý hình ảnh.
- Chuyển đổi (Proxy/Transcode) luồng RTSP sang giao thức WebRTC (WHEP, cổng 8889) hoặc HLS (cổng 8888) truyền trực tiếp tới Frontend để trình duyệt hiển thị livestream.

2.3. BACKEND SERVICE (Spring Boot 3.2.5 / Java 21)
- Trung tâm xử lý nghiệp vụ chính và Quản lý Lưu trữ (Storage Master):
  + Quản lý kết nối trực tiếp với MinIO Object Storage bằng MinIO Java SDK.
  + Quản lý 2 Buckets trên MinIO:
    1) `face-profiles`: Lưu ảnh chân dung chính diện của Cán bộ / Nhân viên / Sinh viên (`{userCode}/{userCode}_front.jpg`).
    2) `security-evidence`: Lưu ảnh bằng chứng vi phạm an ninh từ camera giám sát (`{YYYY-MM-DD}/{cameraCode}/{eventType}_Track{trackId}_{HHmmss}.jpg`).
  + Đảm bảo tính toàn vẹn dữ liệu bằng cơ chế Transaction & Compensating Action (Tự động xóa ảnh trên MinIO nếu Transaction lưu CSDL thất bại).
  + Giao tiếp REST với AI-Service để yêu cầu trích xuất vector khuôn mặt 512d.
  + Lắng nghe sự kiện vi phạm an ninh từ Apache Kafka và bắn WebSocket thông báo tới Frontend.

2.4. AI MICROSERVICE (Python FastAPI + OpenCV + InsightFace + YOLOv8)
- Đóng vai trò là Engine xử lý AI & Thị giác máy tính:
  + Tích hợp module MinIO StorageService để upload trực tiếp ảnh bằng chứng vi phạm (`security-evidence`) và ảnh khuôn mặt đăng ký (`face-profiles`) lên MinIO.
  + **Luồng đăng ký khuôn mặt**: Nhận file ảnh từ Backend qua REST API (`/api/v1/faces/process-registration`), thực hiện đếm số khuôn mặt (`face_count`), cắt khuôn mặt & trích xuất vector embedding 512 chiều, lưu trữ/trả về kết quả JSON cho Backend.
  + **Luồng giám sát thời gian thực**:
    - Nhận luồng video RTSP từ MediaMTX Gateway.
    - Chạy thuật toán YOLOv8 + ByteTrack để phát hiện & theo dõi đối tượng người.
    - Nhận diện khuôn mặt bằng YuNet + InsightFace và đối soát vector với PostgreSQL (`pgvector`).
    - Phân tích hành vi lảng vảng (Loitering Engine) dựa trên vùng hạn chế (ROI polygon).
    - Khi phát hiện vi phạm, chụp frame bằng chứng upload lên MinIO và phát event an ninh qua Apache Kafka.

2.5. INFRASTRUCTURE & STORAGE LAYER
- **PostgreSQL 16 + pgvector**: Cơ sở dữ liệu quan hệ lưu trữ tài khoản, phân quyền, nhật ký cảnh báo và vector khuôn mặt 512 chiều (dùng cho tìm kiếm Cosine Similarity).
- **MinIO Object Storage**: Lưu trữ tập trung toàn bộ file ảnh hồ sơ và ảnh bằng chứng an ninh. Kết nối trực tiếp với cả Backend và AI-Service.
- **Apache Kafka**: Message Broker truyền tải các sự kiện an ninh thời gian thực giữa AI-Service (Producer) và Backend (Consumer).
- **MediaMTX**: Gateway chuyển đổi và phân phối luồng RTSP (tới AI-Service) và WebRTC/HLS (tới Frontend).
